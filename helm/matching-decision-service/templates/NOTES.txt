Reminder: this chart does NOT run database migrations. Before the first deploy to a new
environment, run matching-decision-service/scripts/migrate.ts (and validate-schema.ts) against the
target database out-of-band, then scripts/backfill-matching-decision-service.ts from the monolith
- see matching-decision-service/README.md and MIGRATION_RUNBOOK.md.

This service has no gateway route yet. It receives a live dual-written copy of every swipe/
recruiter-note/detailed-scoring-report row on create/update (see src/dualWrite.ts's
upsertSwipe/upsertRecruiterNote/upsertDetailedScoringReport, gated behind DUAL_WRITE_ENABLED, off
by default). Its own read endpoints are real and ready for a future caller once cut over. The
live-scoring engine itself is untouched.
