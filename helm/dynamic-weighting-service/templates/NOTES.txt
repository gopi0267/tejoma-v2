Reminder: this chart does NOT run database migrations. Before the first deploy to a new
environment, run dynamic-weighting-service/scripts/migrate.ts (and validate-schema.ts) against the
target database out-of-band, then scripts/backfill-dynamic-weighting-service.ts from the monolith
- see dynamic-weighting-service/README.md and MIGRATION_RUNBOOK.md.

This service has no gateway route and no user-facing HTTP surface - and, unlike every other Tier 0
service in this migration, nothing on the monolith side calls it either. The functions it ports
(resolveSkillTiers, computeSeniorityAdjustedWeights, computeDynamicSkillScore,
buildMatchExplanation, hybridRetrieveCandidates) are only reachable on the monolith via
matchingApi.ts's `weighting: 'dynamic'` / `retrieval` options, which no real caller ever sets. Its
own /internal/* endpoints are ready for whichever future caller needs them.
